# 0226 학습 기록

## 1. AI 스켈레톤 코드 학습

### 1-1. 학습 개요

Knowledge Distillation과 LoRA Fine-Tuning을 활용하여 Text-to-SQL Task에 특화된 모델을 학습합니다.  
Teacher Model이 생성한 Pseudo Label을 활용하여 Student Model을 학습하며, LoRA를 적용하여 적은 자원으로 효율적인 파인튜닝을 수행합니다.

### 1-2. 핵심 개념 정리

Knowledge Distillation은 대형 모델의 지식을 소형 모델에 전달하는 방법론입니다. 본 실습에서는 Teacher Model이 생성한 SQL을 정답 데이터처럼 사용하는 Pseudo Labeling 방식을 적용합니다.

LoRA는 전체 파라미터를 학습하지 않고 일부 저차원 행렬만 학습하는 Parameter-Efficient Fine-Tuning 기법입니다. 이를 통해 GPU 메모리 사용량을 줄이면서도 Task 특화 성능을 향상시킵니다.

### 1-3. 실습 내용

데이터셋을 불러오고 EDA를 수행하여 질문 길이, SQL 길이, 난이도 분포 등을 분석합니다.  
Base 모델과 토크나이저를 불러온 뒤, Text-to-SQL 학습에 적합한 입력 포맷으로 전처리를 진행합니다.

이후 LoRA 설정을 적용하여 모델을 Fine-Tuning합니다. Full Fine-Tuning 대신 LoRA를 사용하여 기존 모델의 성능을 유지하면서 특정 Task에 적응하도록 학습합니다.

### 1-4. 모델 평가

test-suite-sql-eval을 활용하여 Execution Accuracy 기준으로 평가합니다.  
단순 문자열 비교가 아니라 실제 데이터베이스 실행 결과 기준으로 정확도를 측정합니다.

-> 학습 결과 predict.txt 파일을 확인했습니다.

### 1-5. 학습 정리

Knowledge Distillation 기반 데이터 구성 과정을 이해합니다.  
LoRA를 활용한 효율적인 Fine-Tuning 방법을 학습합니다.  
Text-to-SQL Task의 구조적 특성과 전처리 전략의 중요성을 확인합니다.


## 2. 온디바이스 추론 Telemetry 및 서버 모니터링 구조 학습

### 2-1. 모바일(온디바이스) 수집 구조 이해

모바일 환경에서 모델 추론 결과를 서버로 전송하는 구조에 대해 학습합니다.

온디바이스에서 수행하는 항목은 다음과 같습니다.

- NDK/JNI, PyTorch, QNN 등을 활용한 모델 실행 구조 이해
- 추론 성공/실패 여부 판단 로직 설계
- 추론 시간(latency) 측정 방식 학습 (start–end timestamp 기반)
- 위험도(score) 계산 후 결과 값 생성

이후 위 정보를 JSON 형태로 구성하여 서버에 POST 방식으로 전송하는 Telemetry 구조를 학습합니다.  
모바일에서는 네트워크 실패 상황을 고려한 비동기 전송 및 재시도 전략의 필요성도 함께 이해합니다.

---

### 2-2. 서버 수집 API 설계

Spring Boot 기반으로 `/telemetry` 엔드포인트를 설계하는 방법을 학습합니다.

- REST API 설계 방식
- DTO를 활용한 요청 데이터 구조 정의
- 모델 버전, 기기 정보, delegate 종류(CPU/NPU), latency, 성공 여부 등의 필드 설계
- 대량 트래픽을 고려한 비동기 처리 방식 검토

서버는 모바일에서 전달받은 추론 로그를 안정적으로 저장하는 역할을 수행합니다.

---

### 2-3. 저장소 설계 및 확장 전략

초기 단계에서는 MySQL 기반 저장 구조를 설계합니다.

- 단일 테이블에 추론 로그 저장
- 인덱스 설계 (model_version, device_type, created_at 등)
- 조회 성능을 고려한 스키마 구성

트래픽 증가 시에는 분석형 데이터베이스로 확장하는 전략을 학습합니다.

- ClickHouse: 대용량 로그 분석에 적합
- BigQuery: 서버리스 기반 대규모 분석 환경

OLTP(MySQL)와 OLAP(ClickHouse/BigQuery)의 차이점도 함께 정리합니다.

---

### 2-4. 지표 집계 설계

모델 운영 관점에서 필요한 주요 지표를 정의합니다.

- 모델 버전별 성공률
- 기기별 평균 latency
- p95, p99 latency
- delegate(CPU vs NPU)별 성능 차이
- 위험도 평균 및 분포

평균뿐 아니라 p95, p99 같은 퍼센타일 지표가 실제 서비스 품질을 판단하는 데 중요하다는 점을 학습합니다.

실시간 집계를 위해 Redis를 활용하는 구조도 함께 검토합니다.

---

### 2-5. 대시보드 구성

수집된 데이터를 시각화하는 방법을 학습합니다.

- Grafana를 활용한 대시보드 구성
- MySQL 또는 분석 DB 연동 방식
- 모델 버전별 추이 그래프
- latency 분포 시각화

또는 Firebase 콘솔 기반 모니터링 방식도 비교 분석합니다.

---

### 2-6. 전체 아키텍처 이해

본 파트를 통해 다음을 정리합니다.

- 온디바이스 추론 결과를 서버로 수집하는 Telemetry 구조 이해
- Spring Boot 기반 수집 API 설계 방법 학습
- 트래픽 증가에 따른 DB 확장 전략 이해
- 모델 운영 관점에서 필요한 핵심 지표 정의
- 모니터링 대시보드 구성 흐름 파악

단순 모델 개발이 아니라, 모델을 실제 서비스 환경에서 운영하기 위한 로그 수집 및 모니터링 체계의 중요성을 이해합니다.
