## 1. 기획 구체화 

### 1-1. 자료조사

해당 기획의 적극적인 서비스 방안을 찾아보기 위해 기존 서비스를 조사했습니다. 

1. 딥페이크 영상 탐지
2. 딥페이크 탐지와 AI 보이스피싱을 동시에 탐지
3. AI 보이스피싱 탐지

이러한 기존 서비스들을 대표적으로 다음과 같은 후속 대응을 제공하고 있었습니다. 

- 미팅 즉시 종료 또는 퇴장 자동수행 설정 가능
- 스미싱·피싱 문자 까지 포함해 전과정을 AI로 탐지·차단하는 “원스톱대응체계” 구축 목표
- 스팸/피싱 의심 번호로 자동 분류, 이후 동일 번호는 사전 차단 가능


### 1-2. 서비스 확정

위의 자료 조사와 개발 환경을 고려해서 다음과 같은 서비스를 결정했습니다. 

① 영상통화 중, 실시간 지인 사칭·딥페이크 위험 판별 (On-device 추론)

② 영상통화 중, 딥페이크일 경우 즉시 딥페이크 감지 알림
        ex_딥페이크 피싱 감지

③ 영상통화 중, 딥페이크일 경우 대화 내용 분석 (On-device 추론)

④ 영상통화 중, 딥페이크 확률 및 대화 분석 기반 위험도 단계별 즉시 알림
        ex_상대에게 계좌번호 및 집주소를 발설하였습니다. 금융 사기가 의심되어 전화를 종료하세요.

⑤ 영상통화 중, 딥페이크일 경우, 금융 앱 실행 차단(보호 모드)

⑥ 영상통화 중, 딥페이크일 경우, 보호자 긴급 알림 시스템

        ex_OOO님이 00시 00분에 xxx-xxxx-xxx 번호로 계좌번호 및 집주소를 발설하였습니다. 피싱이 의심되므로 조치가 필요합니다.

## 2. 역할 분담

성공적인 팀 프로젝트를 위해 역할 분담을 수행했습니다. 

저는 백엔드와 인프라를 맡기로 했습니다. 

### 2-1. 자료 조사

AI팀이 원하는 모델 최적화 모니터링을 위한 자료를 조사했습니다. 

```
실제 기기에서 잘 돌아가는지 확인 (Runtime Monitoring)
모델이 사용자 핸드폰에서 얼마나 빠르게 도는지, 배터리는 얼마나 먹는지 등을 서버로 쏴주는 과정이 필요합니다.

성능 지표 수집: 단순한 앱 크래시뿐만 아니라, 추론 시간(Inference Latency), 메모리 점유율, NPU/GPU 활용도 등을 수집해야 합니다.

추천 도구: Firebase Performance Monitoring: 커스텀 트레이스를 설정해 모델 실행 시간을 측정하고, 기기별/OS 버전별로 성능을 시각화할 수 있습니다.

Sentry: 최근 AI 성능 모니터링 기능을 강화하고 있어, 모바일 환경에서의 모델 성능 저하를 감지하기 좋습니다.

커스텀 텔레메트리(Telemetry): 특정 이벤트(예: 딥페이크 감지 성공/실패)가 발생했을 때 정확도(Accuracy) 피드백을 서버로 보내 별도의 대시보드를 구축하는 방식입니다.
```

### 2-2. 필요한 기술 스택
필요한 기술 스택은 다음과 같습니다. 

```
백엔드/인프라 개발자 (데이터 파이프라인 및 저장)
모바일 기기들에서 쏟아지는 방대한 성능 로그를 안정적으로 받아내고 시각화할 판을 깔아줍니다.

역할: 로그 수집용 API 서버 구축, 데이터베이스(DB) 저장, 대시보드(Grafana 등) 연동을 담당합니다.

인프라 구성: 로그 양이 많아질 경우 메시지 큐(Kafka 등)를 배치하거나, 비용 효율적인 로그 저장소(S3, BigQuery 등)를 관리합니다. 만약 Firebase 같은 상용 솔루션을 쓴다면 인프라 팀의 공수는 줄어들지만, 대신 모바일 팀과 협의해 지표를 어떻게 구조화할지 설계해야 합니다.
```
