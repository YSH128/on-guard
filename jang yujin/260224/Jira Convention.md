# Jira Convention

## 지라 이슈명 템플릿

- Epic, Task 유형만 사용

| **구분** | **템플릿 (작성 규칙)** | **설명** |
| --- | --- | --- |
| **Epic** | **`[기능명] 큰 단위의 목표`** | 서비스의 주요 기능이나 페이지 단위로 작성 |
| **Task** | **`구체적인 작업 내용 (동사형)`** | 깃랩 브랜치를 만들고 실제 코드를 짜는 단위 |
| Component | **`BE`, `FE`, `AI`** | 본인의 파트 선택 |

## 작성 예시

### **Epic 1: [회원] 사용자 인증 및 관리**

- **Task 1:** `feat/로그인 API 개발` (Component: `BE`)
- **Task 2:** `feat/회원가입 화면 UI 구현` (Component: `FE`)
- **Task 3:** `doc/회원가입 방법 README.md 정리` (Component: `FE`)

### **Epic 2: [인식] 생성형 영상 검출**

- **Task 1:** `feat/생성형 영상 검출 모델 호출` (Component: `AI`)
- **Task 2:** `feat/생성형 영상 여부 검출`  (Component: `AI`)
- **Task 3:** `feat/생성형 영상일 경우 팝업 호출` (Component: `AI`)

## 이슈 생성 규칙

- 공통
    - 담당자 최소 1명 지정
    - 파트 컴포넌트 설정 필수
    - Task 생성할 때 반드시 Epic에 연결!
- 순서
    1. **Epic 생성:** **[회원]**, **[제어]** 같은 큰 주제의 에픽을 먼저 만들기.
    2. **Task 연결:**  본인이 할 일을 Task로 만들 때, 반드시 해당 **Epic을 연결**. (이슈 생성 창에 '상위 이슈' 또는 '에픽 링크' 칸이 있습니다.)
    3. **라벨 입력:** 오른쪽 **'컴포넌트'** 칸에 본인 파트(예: `BE`)를 선택.
    4. **브랜치 생성:** 깃랩 브랜치 명은 지라에서 생성되는 이슈 키(예: `PROJ-12`)를 포함하여 `feature/signup-api-PROJ-12` 처럼 작성
    
    ```bash
    # 예시 (팀 프로젝트 S14P11A304)
    git checkout -b feature/signup-api-S14P11A304-28
    ```
    

## 스토리 포인트

- 시간 기반 추정과 달리, **작업의 복잡도, 노력, 위험성을 종합적으로 고려한 상대적인 측정 단위**
    - ex_ 코드 스니펫 수정, API 연동 개발 → API 연동 개발에 더 높은 스토리 포인트 부여
- 시간 기반 추정은 모든 팀원의 작업 속도와 전문성이 동일하다고 가정하기 때문에 현실적이지 않음
- 따라서 스토리 포인트를 이용하여 개인들이 갖는 세부 사항을 추상화하여 팀이 실제 작업 완료에 집중할 수 있게 해줌
