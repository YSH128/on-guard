## 2. 인프라 공부

### 1. 도커란?

- 데이터 or 프로그램을 격리시키는 프로그램

> 컨테이너와 도커 엔진

- 컨테이너:서버 상의 환경을 작은 방으로 분할
- 도커 엔진에 이미지를 활용하여 컨테이너를 생성

---

### 2. 도커의 동작원리

#### 1. 서버와 도커

- 기능적 의미의 서버와 물리적 서버로 구분
- 도커는 리눅스 운영체제에서만 동작

#### 2. 도커 허브와 이미지, 컨테이너

- 이미지로 동일한 컨테이너 여러 개 생성 가능
- 컨테이너로 이미지 생성 가능
- 도커 허브
  - 운영체제만 들어있는 이미지부터 여러 가지 소프트웨어가 포함된 이미지 등 제공
- 안전한 컨테이너 이미지 고르는 법
  - 공식 이미지 사용
    - 특정 운영체제 및 버전으로 한정된 경우가 종종 있어 주의 필요
  - 커스텀 이미지를 직접 만들어 사용
    - 운영체제가 포함된 이미지에 소프트웨어를 넣는 것은 난이도가 낮음

- 다양한 형태의 조합
  - 한 컨테이너에 모든 프로그램
  - 한 컨테이너에 하나의 프로그램

#### 3. 도커 컨테이너의 생애주기와 데이터 저장

- 새로운 버전이 나오면 갈아탄다
- 데이터를 보호하기 위해 \*\*도커가 설치된 물리적 서버(호스트)의 디스크를 마운트
  > 예시

`docker run -v /data/database:/app/data myimage`

/data/database = 물리 서버의 실제 폴더

/app/data = 도커 컨테이너에서 보이는 경로
결과: 컨테이너 내에서 /app/data에 접근하면 서버의 /data/database 데이터를 사용할 수 있음

- 프로그램을 개발할 때 다른 저장소에 저장하지 않는 경우 주의

- 도커의 주 용도
  - 동일한 개발환경 제공
  - 새로운 버전의 테스트
  - 동일한 서버가 여러 대 필요한 경우
