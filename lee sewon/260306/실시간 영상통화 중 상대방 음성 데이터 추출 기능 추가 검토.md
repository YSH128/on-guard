# 실시간 영상통화 중 상대방 음성 데이터 추출 기능 추가 검토

> **작성일**: 2026.03.06  
> **작성자**: 이세원

---

## 📌 개요

영상통화 중 상대방의 음성 데이터는 **일반 앱에서 접근 가능한 형태로 제공되지 않는다.**

통신사 영상통화의 경우 아래와 같은 경로를 거쳐 스피커로 출력되며, 이 과정은 **시스템 레벨**에서 처리된다.

```
기지국 → 모뎀 칩 (패킷 복호화 및 디코딩) → Android Audio Framework → 스피커 출력
```

---

## 🔍 접근 방법별 검토

### 1) Shizuku 기반 시스템 권한 접근 시도

| 항목 | 내용 |
|------|------|
| **방법** | `adb shell` 권한으로 Audio 정책 접근 시도 |
| **결과** | ❌ **실패** — 오디오 캡처 권한 검증에 의해 거부됨 |

---

### 2) Root 기반 AudioFlinger 후킹 검토

| 항목 | 내용 |
|------|------|
| **방법** | AudioFlinger 내부 버퍼에 직접 접근 |
| **가능 여부** | 기술적으로 내부 버퍼 접근 가능 |
| **결과** | ⚠️ **시도하지 않음** — 루팅 필요 및 정책/법적 리스크 존재 |

---

### 3) 카카오 페이스톡 화면녹화 오디오 후킹 검토

#### 3-1) Usage 정책 제한

- 카카오 페이스톡 내 영상통화 음성은 **usage 정책으로 접근 제한**되어 있음

#### 3-2) REMOTE_SUBMIX 오디오 캡처

- `REMOTE_SUBMIX` 오디오 캡처 **불가능** 확인

#### 3-3) screenrecord 세그먼트 녹화 방식

| 항목 | 내용 |
|------|------|
| **방법** | `screenrecord`로 짧은 세그먼트를 반복 녹화 → 각 세그먼트에서 `MediaExtractor`로 오디오 트랙을 PCM 디코딩 → 콜백으로 전달 |
| **결과** | ❌ **실패** — `screenrecord`에 음성이 저장되지 않음을 확인 |

#### 💡 결론: 삼성 기기 화면 녹화 앱에서 페이스톡 상대방 소리가 수음되는 이유

- 삼성 화면 녹화 앱은 **`system` (UID=1000)** 또는 **삼성 특권 앱**이기 때문
- **Mixer 통과 유무**에 따라 페이스톡과 통신사 영상통화의 녹음 가능 여부가 갈림

| 구분 | Mixer 통과 | 녹음 가능 여부 |
|------|-----------|---------------|
| 카카오 페이스톡 | O (VoIP) | ✅ 삼성 특권 앱으로 가능 |
| 통신사 영상통화 | X (모뎀 직접 처리) | ❌ 불가 |

---

### 4) VPN 패킷 레벨 접근 검토

| 항목 | 내용 |
|------|------|
| **방법** | VPN을 통한 SRTP 패킷 캡처 |
| **SRTP 패킷 캡처** | ✅ 가능 여부 확인 완료 |
| **복호화** | ⚠️ 추가 조사 필요 — 현재로서는 복호화를 위한 키 접근이 **root 권한 단위에서만 가능**한 것으로 파악 |

## 📊 검토 결과 요약

| # | 접근 방법 | 결과 | 비고 |
|---|----------|------|------|
| 1 | Shizuku (adb shell 권한) | ❌ 거부됨 | 오디오 캡처 권한 검증 |
