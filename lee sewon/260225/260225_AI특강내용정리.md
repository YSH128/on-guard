# 🔊 특강 - 이론

### ✅ RAG (Retrieval-Augmented Generation)

- **정의:** 외부 지식 베이스(Knowledge Base)에서 정보 검색(Retrieval) → 검색된 정보를 바탕으로 LLM이 답변을 생성(Generation)
- RAG 나이브


    | 단계 | 구성 요소 | 사용 모델 | 역할 |
    | --- | --- | --- | --- |
    | 1 | Structured / Unstructured Data | - | 원본 지식 데이터 준비 |
    | 2 | Chunks | - | 문서를 작은 단위로 분할 |
    | 3 | Embedding | Text Embedding Model | 각 Chunk를 벡터로 변환 |
    | 4 | Vector DB 저장 | - | 벡터를 저장하고 유사도 검색 가능하게 함 |
    | 5 | Retrieval | Embedding + Vector Search | 질문과 유사한 Chunk 검색 (Top-K) |
    | 6 | Generation | Large Language Model | 검색된 문서를 근거로 답변 생성 |

### ✅ Hugging face 라이브러리 예시

| 라이브러리 | 역할 | 언제 사용 | 핵심 기능 |
| --- | --- | --- | --- |
| **transformers** | 사전학습 모델 로드 및 추론/학습 | LLM, BERT, ViT 등 모델 사용할 때 | 모델 로딩, 토크나이저, Trainer, 파인튜닝 |
| **datasets** | 대규모 데이터셋 관리 | 학습용 데이터 불러올 때 | 데이터 로딩, 전처리, streaming, map |
| **peft** | 경량 파인튜닝 | GPU 메모리 부족할 때 | LoRA, QLoRA, Prefix/Prompt Tuning |
| **trl** | 강화학습 기반 튜닝 | RLHF, DPO 등 정렬 학습할 때 | PPOTrainer, DPOTrainer, SFTTrainer |

### ✅ **PEFT(경량 파인튜닝)** 기법

- **Adapter :** 모델 내부에 작은 모듈 추가
    - Linear 레이어를 중간에 넣음 → 비선형 문제를 풀기 어려움 (자연어 = 비선형적)
- **Prefix :** Attention 앞에 가상 토큰 추가 (task 전용)
- **Prompt :** 입력 프롬프트 벡터만 학습 (general)
- **P-tuning :** MLP나 LSTM 같은 네트워크로 생성된 prefix 벡터 사용
- **LoRA** ⭐⭐⭐ **:** 기존 weight에 low-rank update
- **IA³** : Attention과 FFN 내부의 activation에 “스케일 벡터”를 곱해서 조정
- **MORA :** 단일 low-rank(r) 대신 여러 rank 모듈을 조합하거나 레이어별로 다른 rank 사용
- **DORA :** weight를 **방향(direction)** 과 **크기(magnitude)** 로 분해 → 방향은 LoRA처럼 low-rank로 학습 / 크기(norm)는 별도 스케일 파라미터로 학습

### ✅ **PLHF 방법론 : PPO**

- PPO : 강화학습에서 정책을 최적화하기 위한 알고리즘 중 하나
- 문제점 : 긴 학습 framework 및 고비용 발생

### ✅ DPO (Direct Preference Optimization)

- 사람의 선호 데이터(좋은 응답 vs 나쁜 응답 쌍)를 직접 활용해 **강화학습 없이** 모델을 최적화하는 방법.
- PPO처럼 보상모델 + RL 단계를 거치지 않고, “선호된 응답의 확률은 높이고 / 비선호 응답의 확률은 낮추는” 방식으로 **직접 로그 확률을 최적화**

# 🧠 인사이트

- **내가 새롭게 알게 된 점**
    - 일부 연구 결과, **Prompt Tuning이 Prefix Tuning보다 더 좋은 성능**을 보였다는 보고
    - Adapter은 **Linear 레이어**를 중간에 넣어서 **비선형 문제를 풀기 어려움** ⇒ MLP로 생성된 **P-tuning이 더욱 효과적인 성능 보임**
- **추가 조사 및 공부**
    - **Prompt Tuning이 Prefix Tuning보다 더 좋은 성능을 보이는 경우**
        - 모델이 매우 큰 경우 (Scale 효과)
        - 단일 태스크 + 분류/간단 NLU 작업
        - 충분한 프롬프트 길이 허용 시
        - 멀티태스크 환경 (성능보단 운영 효율성 측면에서 굿)
