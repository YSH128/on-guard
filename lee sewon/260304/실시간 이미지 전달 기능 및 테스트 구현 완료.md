## 1. 오늘 한 일

### 1-1. JNI 프레임 전달 파이프라인 구현

캡처된 영상통화 프레임(RGBA byte[])을 JNI를 통해 C++ NDK AI 모듈로 전달하는 구조 완성.

```
ScreenCaptureManager (프레임 캡처)
    ↓ onFrameCaptured(buffer, width, height, rowStride)
VideoCallDetectService
    ↓ (detector as? RealDeepfakeDetector)?.feedFrame(...)
RealDeepfakeDetector
    ↓ NativeDeepfakeBridge.requestDeepfakeDetection(...)
    ↓ [JNI 경계]
C++ NDK — request_deepfake_detection(videoData, audioData)
    ↓ JSON 반환 {"detected":1,"roi":[...]}
RealDeepfakeDetector.parseResult()
    ↓ DeepfakeDetectionResult
VideoCallDetectService → 경고 오버레이 표시/해제
```

### 1-2. 신규 생성 파일

| 파일 | 패키지 | 역할 |
|---|---|---|
| `NativeDeepfakeBridge.kt` | `data.source.jni` | JNI `external fun` 선언, 안전한 `loadLibrary()` |
| `RealDeepfakeDetector.kt` | `data.source.detector` | JNI 호출 + JSON 파싱 + 콜백 전달 |
| `DeepfakeDetectionResult.kt` | `domain.model` | 감지 결과 데이터 클래스 (detected, roi) |

### 1-3. Stub 테스트 모듈 (ADB 수동 트리거)

`BroadcastTriggerDetector`를 통해 NDK 없이도 딥페이크 감지 결과를 주입하여 테스트 가능.

## 3. ADB 테스트 명령어

> 전제: 앱 실행 + 보호 시작 + 영상통화 중 (통화 + 카메라 사용)

### 딥페이크 감지 트리거 (오버레이 ON)
```bash
adb shell am broadcast -a com.s14p21a404.shutter.FAKE_DETECTION \
  --ei detected 1 \
  --ef roi_min_x 0.3 --ef roi_min_y 0.22 \
  --ef roi_max_x 0.45 --ef roi_max_y 0.567
```

### 안전 판정 트리거 (오버레이 OFF)
```bash
adb shell am broadcast -a com.s14p21a404.shutter.FAKE_DETECTION --ei detected 0
```

## 4. AI 응답 JSON 형식

```json
{
    "detected": 1,
    "roi": [0.3, 0.22, 0.45, 0.567]
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `detected` | `int` (0 or 1) | 딥페이크 검출 여부 |
| `roi` | `float[4]` | 의심 영역 상대좌표 `[minX, minY, maxX, maxY]` (0.0~1.0) |

JSON 파싱은 `RealDeepfakeDetector.parseResult()`에서 `org.json.JSONObject` 사용 (Android 내장, 별도 의존성 불필요).

## 5. JNI 전달 데이터

| 항목 | 값 |
|---|---|
| `videoBuffer` | `ByteArray` — RGBA_8888 프레임 (padding 포함) |
| `width` | `Int` — 기기 화면 너비 (px) |
| `height` | `Int` — 기기 화면 높이 (px) |
| `rowStride` | `Int` — Image.Plane rowStride (행 바이트, padding 포함) |
| `audioBuffer` | `ByteArray?` — 현재 `null` (향후 구현) |
